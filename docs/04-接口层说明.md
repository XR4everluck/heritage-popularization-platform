# 阶段4：Controller 接口层开发说明（核心 REST 接口）

> 阶段4目标：基于已有 entity/mapper/service，生成前台用户与后台管理两大模块的完整 REST 接口。
> 全部接口统一返回 `Result{code,msg,data}`，遵循 GET 查询 / POST 新增 / PUT 修改 / DELETE 删除 规范，分页使用 MyBatis-Plus `Page`。
> **暂不做权限拦截**（按要求先完成基础接口功能方便调试），用户身份由前端传 `userId` 参数，接入 JWT 时仅需改为登录态解析，接口路径不变。

## 3. 设计与实现要点

1. **薄控制器 + 厚服务**：控制器只做参数接收与 Result 包装；跨表逻辑全部下沉到 ServiceImpl——`SysUserServiceImpl`（注册/登录/资料）、`HeritageInfoServiceImpl`（分类名组装/浏览量）、`UserCollectionServiceImpl`（收藏联动）、`UserCommentServiceImpl`（VO 组装/归属校验）、`StudyProgressServiceImpl`（进度 upsert）；
2. **DTO/VO 分层**：入参用 DTO（`dto/`：Login/Register/UserUpdate/Comment/Progress，带 `@Validated` 校验注解，非法参数由全局异常处理器统一转 400）；出参用 VO（`vo/`：HeritageVO 含分类名、CommentVO 含评论人/非遗名、CollectionVO、ProgressVO），关联信息通过**批量查询+内存组装**实现（一次查询映射，避免循环单查 N+1）；
3. **安全细节**：
   - 登录失败统一提示"用户名或密码错误"，不暴露账号是否存在；禁用账号单独提示；
   - `updateProfile` 使用专用 DTO，role/status/password 等敏感字段不可被越权修改；
   - 删除本人评论先校验归属；进度 upsert 以章节记录为准校验课程归属，防止进度挂错课程；
   - 浏览量/收藏数用 `setSql("view_count = view_count + 1")` 数据库原子自增（静态片段，无外部输入拼接）；
   - 所有条件查询均为 MyBatis-Plus 预编译参数绑定，无 SQL 注入面。
4. **逻辑删除自动生效**：分类/非遗/课程/评论/公告的删除均为 `UPDATE deleted=1`；前台查询自动过滤已删除数据（含 `listByIds` 批量查询）；章节/收藏/进度按设计物理删除；
5. **密码算法统一**：种子密码密文由 `$2b$` 切换为 `$2a$` 前缀（对短密码两者哈希完全等价，兼容性最佳），与 Hutool `BCrypt.hashpw/checkpw` 一致，并有 `BCryptSeedTest` 单测锁定。
