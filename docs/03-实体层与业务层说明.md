# 阶段3：实体层 + 数据层 + 业务层代码生成说明

> 阶段3目标：基于已设计的 10 张数据表，使用 MyBatis-Plus 生成 Entity、Mapper、Service 三层代码，完成基础 CRUD 封装。
> 生成原则：不生成 XML，全部使用 MyBatis-Plus 内置方法；每个类带中文注释。

---

## 1. 代码生成总览

共生成 **40 个类**，目录均在 `backend/src/main/java/com/heritage/` 下：

| 层 | 包路径 | 生成内容 | 约定 |
| --- | --- | --- | --- |
| 实体层 | `entity` | 10 个实体类 | `@TableName` 表名映射、`@TableId(type = IdType.AUTO)` 自增主键、`@TableField` 字段映射、逻辑删除字段加 `@TableLogic`、Lombok `@Data` |
| 数据层 | `mapper` | 10 个 Mapper 接口 | `extends BaseMapper<T>` + `@Mapper`，内置单表 CRUD |
| 业务层 | `service` | 10 个 Service 接口 | `extends IService<T>`，内置业务级 CRUD 与批量操作 |
| 业务实现 | `service.impl` | 10 个实现类 | `extends ServiceImpl<M, T> implements XxxService` + `@Service` |

业务方法调用链（接口层阶段使用）：`Controller → XxxService（IService 方法）→ XxxMapper（BaseMapper 方法）`。

## 2. 各模块文件路径清单

### 2.1 实体层 `backend/src/main/java/com/heritage/entity/`

| 类文件 | 对应表 | 说明 |
| --- | --- | --- |
| `SysUser.java` | sys_user | 系统用户（role 区分 user/admin；password 字段标注 `@JsonProperty(WRITE_ONLY)`，序列化时不外泄） |
| `HeritageCategory.java` | heritage_category | 非遗分类 |
| `HeritageInfo.java` | heritage_info | 非遗项目（核心内容表） |
| `Course.java` | course | 课程 |
| `CourseChapter.java` | course_chapter | 课程章节 |
| `UserCollection.java` | user_collection | 用户收藏（无 deleted，物理删除） |
| `UserComment.java` | user_comment | 评论 |
| `StudyProgress.java` | study_progress | 学习进度（无 deleted，物理删除） |
| `Banner.java` | banner | 轮播图 |
| `Notice.java` | notice | 系统公告 |

实体设计要点：

1. **主键**：`@TableId(type = IdType.AUTO)`，插入后 MyBatis-Plus 自动将自增 ID 回填到实体对象；
2. **逻辑删除**：含 `deleted` 字段的表（sys_user、heritage_category、heritage_info、course、user_comment、notice）在字段上标注 `@TableLogic`——`removeById` 自动转为 `UPDATE ... SET deleted=1`，所有查询自动拼接 `deleted=0` 条件；course_chapter、user_collection、study_progress 按建表设计为物理删除；
3. **字段映射**：所有数据列显式标注 `@TableField("列名")`，Java 属性驼峰命名与数据库下划线列一一对应；
4. **时间字段**：统一使用 `java.util.Date`，配合 `application.yml` 中 Jackson 的 `yyyy-MM-dd HH:mm:ss` 全局格式化输出；
5. **create_time/update_time 由数据库默认值维护**：MyBatis-Plus 插入/更新时默认忽略 null 字段（field-strategy NOT_NULL），时间列走 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE CURRENT_TIMESTAMP`，无需代码填充。

### 2.2 数据层 `backend/src/main/java/com/heritage/mapper/`

`SysUserMapper.java`、`HeritageCategoryMapper.java`、`HeritageInfoMapper.java`、`CourseMapper.java`、`CourseChapterMapper.java`、`UserCollectionMapper.java`、`UserCommentMapper.java`、`StudyProgressMapper.java`、`BannerMapper.java`、`NoticeMapper.java`

统一形式（以 SysUserMapper 为例）：

```java
@Mapper
public interface SysUserMapper extends BaseMapper<SysUser> {
}
```

启动类已加 `@MapperScan("com.heritage.mapper")`，`@Mapper` 与其配合双保险。内置方法示例：`insert / deleteById / updateById / selectById / selectList / selectPage`，全部使用预编译参数绑定，无 SQL 注入风险。

### 2.3 业务层 `backend/src/main/java/com/heritage/service/`

`SysUserService.java`、`HeritageCategoryService.java`、`HeritageInfoService.java`、`CourseService.java`、`CourseChapterService.java`、`UserCollectionService.java`、`UserCommentService.java`、`StudyProgressService.java`、`BannerService.java`、`NoticeService.java`

### 2.4 业务实现 `backend/src/main/java/com/heritage/service/impl/`

`SysUserServiceImpl.java`、`HeritageCategoryServiceImpl.java`、`HeritageInfoServiceImpl.java`、`CourseServiceImpl.java`、`CourseChapterServiceImpl.java`、`UserCollectionServiceImpl.java`、`UserCommentServiceImpl.java`、`StudyProgressServiceImpl.java`、`BannerServiceImpl.java`、`NoticeServiceImpl.java`

统一形式（以 SysUserServiceImpl 为例）：

```java
@Service
public class SysUserServiceImpl extends ServiceImpl<SysUserMapper, SysUser> implements SysUserService {
}
```

`IService` 已提供的常用业务方法（接口层阶段直接调用，无需重写）：`save / saveBatch / removeById / updateById / getById / getOne / list / count / page / lambdaQuery()`。业务模块需要跨表组装等复杂逻辑时，再在对应 Service 接口中追加方法并在实现类实现。

## 3. 测试：`backend/src/test/java/com/heritage/MyBatisPlusSmokeTest.java`

数据层冒烟测试，直接使用 `application.yml` 配置的数据源，真实连库验证：

1. `save()` 新增分类 → 自增主键回填到实体；
2. `page()` 分页查询（单页 2 条、总数 ≥ 6）→ 分页插件生效；
3. `removeById()` → 数据库中 `deleted` 变为 1（逻辑删除，记录仍在）；
4. `getById()` → 逻辑删除后的记录业务层不可见（自动拼接 `deleted=0`）；
5. 测试数据最终用原生 SQL（参数绑定）物理清理，不污染演示数据。

> **注意**：数据库不可达（如尚未在 yml 中配置真实账号密码）时该测试自动跳过（skipped 而非 failed），不影响 `mvn test` 结果；配置好数据库后它会自动转为真实执行。
