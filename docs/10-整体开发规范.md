# 10 - 整体开发规范（评审稿 v1.0）

> 项目：非遗知识教学平台（毕业设计）
> 前端：Vue 3 + Vite + Element Plus + TypeScript（现状为 JS，本规范定义迁移策略）
> 后端：Spring Boot（本规范以前端为主，后端仅涉及接口对接约定）
> 页面风格参考：中国非物质文化遗产网 https://www.ihchina.cn/ 的**布局结构**。
> ⚠️ 仅参考其信息架构与版式骨架（导航 / 横幅 / 分区 / 列表 / 详情 / 页脚的组织方式），
> **禁止**抓取、反编译或照抄其 DOM 结构、CSS 源码、图片素材与文案。

## 0. 评审决策点（请先确认）

本规范中以下三条属于方向性决策，评审时优先确认：

| # | 决策点 | 本规范的建议 |
|---|--------|--------------|
| D1 | TypeScript 采用策略 | **渐进式引入**：新增文件一律 `.ts` / `lang="ts"`，存量 `.js` 文件"改到即转"，配置 `allowJs` 保证共存期可构建。不搞一次性全量重写 |

## 1. 总体设计原则

1. **庄重克制**：政务文化属性优先。禁用粒子背景、跑马灯、霓虹发光、大面积渐变文字、弹跳/抖动动效。动效只用于表达状态变化（见第 7 节）。
2. **内容为王**：非遗项目本身是主角。版式、留白、层级为内容服务，装饰元素（回纹、水波纹等）仅作低饱和度点缀，不得干扰阅读。
3. **一致性高于个性**：任何页面不得私自定义颜色、字号、间距，一律引用设计令牌（第 5 节）。
4. **可访问性是底线而非加分项**：语义化标签、键盘可达、对比度达标为每个页面的验收前置条件（第 9 节）。
5. **渐进增强**：核心内容（文字、图片）在不支持 JS 新特性时仍可读；地图等重交互模块允许降级为列表展示。

## 2. 布局结构规范（参考 ihchina.cn 版式骨架）

只约定"骨架"，不约定具体像素复刻。各版块自上而下：

### 2.1 全局框架
- **顶部通栏**：可含一条辅助信息条（如"国家级非遗代表性项目名录"类引导语），主体为 横向导航栏。
- **导航栏**：左侧站点标识（文字标识即可，勿用临摹官方 logo），中部主导航（首页 / 非遗项目 / 传承人 / 非遗地图 / 课程学习 / 公告资讯），右侧搜索入口与登录入口。高度约 64–72px，吸顶可选（吸顶时加底边 1px 分隔线，不做毛玻璃透明变化）。
- **页脚**：深色底（墨黑/黛青），含栏目快捷链接、项目说明（毕业设计声明）、备案/版权占位。三到四栏栅格，移动端单列堆叠。

### 2.2 首页分区（自上而下）
1. **主横幅**：轮播图（复用现有 `BannerCarousel`），图上叠加短标题+引导按钮，切换为淡入淡出，禁止 3D 翻转。
2. **公告/资讯条**：横幅下方一栏，左侧"公告"标签 + 最新 1–3 条滚动或列表展示。
3. **非遗项目精选**：分区标题（居中，两侧短装饰线）+ 卡片栅格（4 列 / 平板 3 列 / 移动 2 列），复用 `HeritageCard`。
4. **数据概览带**：一条横向统计带（如收录项目数、传承人数、课程数），数字静态呈现即可；若做计数动画，仅页面进入视口时播一次，时长 ≤ 1s。
5. **课程/教学区块**：`CourseCard` 栅格 + "查看全部"链接。
6. **地图入口区块**：一张静态引导图或内嵌地图（小尺寸），点击跳转非遗地图页。

### 2.3 列表页（非遗项目 / 传承人 / 资讯）
- 面包屑（`nav[aria-label="面包屑"]`）。
- **左窄右宽**两栏：左侧分类树/筛选栏（约 240px，移动端折叠为顶部筛选抽屉），右侧卡片栅格或列表。
- 筛选控件统一用 Element Plus（`el-select` / `el-cascader` / `el-input`），高度统一 40px。
- 底部分页器居中，展示总数。

### 2.4 详情页
- 面包屑 + 主标题（标题下带发布时间、来源等元信息行，浅灰小字）。
- 正文单栏，最大宽度约 800px 居中，图文混排；富文本由 wangEditor 产出，后台需按 5.4 节约束产出干净 HTML。
- 正文右侧或尾部：关联推荐（相关项目/传承人），复用卡片组件。
- 详情页不做侧边悬浮操作栏（克制原则），分享、收藏收敛到标题行右侧图标按钮。

### 2.5 非遗地图页
- 地图占主体（全宽或左 3/4），右侧/下方为省份筛选与项目列表联动区。
- 省份筛选以**弹窗（Dialog）或侧栏面板**呈现：省级行政区选择 → 联动地图点位与列表。详见第 8 节。

## 3. 工程结构与命名规范

```
frontend/src/
├── api/            # 接口模块，按业务域拆分（现有 admin/front/user/file 保持）
├── assets/         # 静态资源；图片放 assets/images/<模块>/
├── components/     # 跨页面复用的展示组件（kebab-case 或现有 PascalCase 文件名，保持 PascalCase）
├── composables/    # 组合式函数（新增目录），如 useAuth.ts、useProvince.ts
├── constants/      # 常量与枚举（新增目录），如类别、省份、批次等字典
├── layout/         # FrontLayout / AdminLayout
├── router/         # 路由；超过 150 行拆分为 modules/front.ts、modules/admin.ts
├── store/          # Pinia store，按域拆分，命名 useUserStore
├── styles/         # 全局样式：tokens.css、global.css、element-theme.css
├── types/          # 全局 TS 类型（新增目录）：api.d.ts、models.ts
├── utils/          # 纯函数工具：request、format、validators
└── views/          # 页面级组件，一个路由一个目录（见下）
```

命名约定：
- 组件文件 PascalCase（`HeritageCard.vue`）；组合式函数 camelCase 且 `use` 前缀；常量文件 camelCase，导出常量 UPPER_SNAKE_CASE。
- 视图组件一律 `defineOptions({ name: 'XxPage' })` 或文件名即语义，配合路由 `name` 一致（如 `HeritageDetail`）。
- 路由懒加载：所有 front/admin 页面用 `() => import(...)` 动态导入。
- 禁止新增 `any` 出现在提交的 `.ts` 文件中；确需绕过用 `unknown` + 收窄或 `// eslint-disable` 说明理由。

## 4. TypeScript 规范（含迁移策略，对应决策 D1）

### 4.1 渐进式迁移
1. 新增 `tsconfig.json`（`strict: true`，`allowJs: true`，`noEmit`），新增 `src/vite-env.d.ts`。
2. 新文件一律 TypeScript：`.ts`（逻辑）、`<Comp>.vue` 内 `<script setup lang="ts">`。
3. 存量 `.js`：**谁改谁转**——对一个文件做功能性修改时顺手迁移为 TS；纯样式/文案微调不强求。
4. 迁移顺序建议：`utils/request.js` → `api/*.js`（补接口返回类型）→ `store/user.js` → 各视图。
5. `package.json` 增补：`typescript`、`vue-tsc`，`build` 脚本改为 `vue-tsc --noEmit && vite build`（首次接入允许先 `--noEmit` 仅检查不卡构建，两周后转为强制）。

### 4.2 类型约定
- 接口响应统一声明泛型：`Result<T>`（`code / msg / data`），`request.js` 迁移后签名为 `request<T>(config): Promise<T>`。
- 领域模型集中在 `types/models.ts`：`HeritageItem`、`Inheritor`、`Course`、`ProvincePoint` 等，字段以后端接口文档（docs/08）为准。
- 组件 Props/Emits 用类型声明：`defineProps<{ item: HeritageItem; loading?: boolean }>()`、`defineEmits<{ (e: 'select', id: number): void }>()`，禁用运行时对象 + 类型双写的冗余写法（二选一，选类型式）。
- 字典/枚举用 `as const` 对象而非 `enum`（与 Vite tree-shaking 友好）。

## 5. 设计令牌与样式规范

现有 `styles/global.css` 中的国风变量体系**保留并成为唯一色彩来源**，整理拆分为 `tokens.css`：

### 5.1 色板（国风，庄重基调）
| 令牌 | 值 | 用途 |
|---|---|---|
| `--gq-primary` | `#c0392b` 朱红 | 主操作、当前态、品牌强调。**大面积禁用**，仅按钮/选中态/标签点缀 |
| `--gq-secondary` | `#2c3e50` 黛青 | 导航底色、页脚、次级强调 |
| `--gq-gold` | `#d4af37` 鎏金 | 装饰线、徽标点缀，仅细线与小面积 |
| `--gq-bg` | `#f7f4ee` 宣纸米白 | 页面背景 |
| `--gq-text` / `--gq-text-secondary` | `#1a1a1a` / `#666666` | 正文 / 辅助文字 |
| `--gq-border` / `--gq-card` | `#e8e3d9` / `#ffffff` | 边框 / 卡片 |

规则：
- 页面以米白+墨字为主体（≥ 70% 面积），朱红占比 ≤ 10%，鎏金 ≤ 2%。
- 对比度强制：正文文字对背景 ≥ 4.5:1；`#666666` 只允许用于 ≥ 14px 文字。
- Element Plus 主色映射沿用现有 `--el-color-*` 覆写方案，禁止组件内散写 `color: #c0392b`。

### 5.2 字体
- 标题：思源黑体/系统黑体，700；正文：思源宋体/宋体（沿用现有 `--font-*` 变量）。
- 字号阶梯：12 / 14 / 16 / 18 / 22 / 28 / 36px，超出需说明理由；行高正文 1.75（中文长文阅读），标题 1.3。
- 富文本详情页正文 ≥ 16px，段距 ≥ 0.75em，两端对齐禁用（中文避免拉伸）。

### 5.3 间距 / 圆角 / 阴影
- 间距基准 4px 序列：4 / 8 / 12 / 16 / 24 / 32 / 48。
- 圆角：控件 4px、卡片 8px、弹窗 12px；**全局统一小圆角**，不用 16px+ 大圆角（政务感）。
- 阴影仅两档：卡片 `0 2px 8px rgba(26,26,26,.06)`、弹层 `0 8px 24px rgba(26,26,26,.12)`。禁用彩色阴影/发光。
- 装饰：区块标题可用"两侧短横线 + 中心字"或 1px 鎏金下划线；回纹等纹样如使用，透明度 ≤ 8% 且不随滚动位移。

### 5.4 富文本产出约束（配合 wangEditor）
后台编辑器仅允许：h2/h3、p、ul/ol、img、blockquote、table。粘贴外部内容时清除行内颜色与字体（详情页正文样式由 `HeritageDetail` 的 `.rich-content` 统一接管），保证全站正文观感一致。

## 6. Vue 组件开发规范

1. 全部使用 `<script setup>` + Composition API；禁用 Options API 新增代码，禁用 `this`。
2. 单文件区块顺序：`<script setup lang="ts">` → `<template>` → `<style scoped>`。样式必须 `scoped`，全局样式只进 `styles/`。
3. 单组件 ≤ 300 行（不含模板内长列表）；视图页超过 500 行必须拆分：
   - 独立视觉块 → `components/`；
   - 带状态逻辑的块 → 页面内子组件或抽 `composables/`；
   - 纯数据加工 → `utils/`。
4. 响应式：`ref` 优先；对象/列表型复杂状态用 `reactive` 时命名大驼峰式变量前加 `state` 前缀；props 解构只在保留响应式的写法下使用（Vue 3.5+ 支持默认值语法）。
5. 副作用：请求统一在 `onMounted` 或由路由触发的 action 中；`watch` 必须考虑卸载清理；定时器（公告滚动、轮播）在 `onUnmounted` 清除。
6. 组件通信：父子 props/emit；跨层用 provide/inject 须注释 key 定义；全局状态只进 Pinia。
7. Element Plus 使用约定：
   - 全量引入保持现状（毕业设计规模可接受），但**图标**改为按需导入，替换 main.js 中的全量图标注册（当前注册了全部图标，包体积浪费）。
   - 消息反馈统一 `ElMessage`（轻提示）/ `ElMessageBox`（确认）；页面级错误用 `el-empty` + 重试按钮。
   - 表格、表单、分页在 admin 端使用；前台展示页尽量少用 EP 组件以贴近国风观感。
8. 路由守卫：登录态校验集中在 `router/index.ts` 的 `beforeEach`，页面内不再散写 token 判断。

## 7. 动效与状态反馈规范（克制版）

### 7.1 允许的动效（全部 CSS transition 优先）
| 场景 | 规格 |
|---|---|
| 页面路由切换 | 淡入 200ms，位移 8px 内 |
| 卡片悬停 | 上移 2px + 阴影升至卡片档，200ms `ease-out` |
| 弹窗/抽屉 | 淡入 + 轻微缩放 0.98→1，240ms |
| 骨架屏 | 列表/详情请求期间展示，`el-skeleton` |
| 数字概览 | 进入视口计数一次，≤ 1s，`prefers-reduced-motion` 时直接展示终值 |

### 7.2 禁止清单
粒子/星空背景、鼠标跟随特效、视差滚动、霓虹发光、渐变文字大面积使用、抖动表单、3D 轮播、无限循环呼吸光。

### 7.3 状态补齐（沿用既有清单，继续有效）
- 每个数据列表必须有：加载（骨架屏）、空（`el-empty` + 引导动作）、错误（错误提示 + 重试）三态；详情页同。
- 全局 `app.config.errorHandler` 兜底保留；接口层错误统一在 `request.js` 拦截器转译为用户可读文案，组件内不重复 toast。

## 8. 非遗地图模块规范（高德 JSAPI 2.0）

### 8.1 技术要点
- 以 `@amap/amap-jsapi-loader` 按需加载，禁止 `<script>` 全局标签注入。
- Key 配置：`VITE_AMAP_KEY` + `VITE_AMAP_SECURITY_CODE` 放 `.env`；`.env.production` 中 Key 属于公开凭据可打包，但 **securityJsCode 必须走服务端代理**（nginx `/_maps` 转发 `https://restapi.amap.com`），避免密钥明文暴露。开发环境写入 `.env.development`（不入库，提供 `.env.example`）。
- 点位数据由后端接口提供（项目名、类别、经纬度、省份），前端不再内置大体积 GeoJSON；现有 `china-geojson.json` 在切换后删除。
- 点位渲染：`AMap.Marker` + 自定义国风样式的 `AMap.MarkerCluster`（类别聚合）；信息窗体内容用 Vue 组件渲染（`AMapVue` 封装或手动 mount），含项目名 + "查看详情"链接。

### 8.2 省份筛选弹窗
- 入口按钮"按省份浏览"打开 Dialog：左侧省份列表（或 34 省简图点击，简图用自绘 SVG，不抓取三方素材），支持搜索框过滤省份名。
- 选择省份 → 关闭弹窗 → 地图 `setFitView` 到该省 + 右侧列表刷新该省项目。
- 弹窗与地图联动状态抽为 `composables/useProvinceFilter.ts`，地图初始化抽 `composables/useAmap.ts`（统一处理加载失败兜底：显示"地图加载失败"+ 省份列表降级）。

### 8.3 无障碍与降级
- 地图容器需 `role="application"` + `aria-label="中国非物质文化遗产分布地图"`，并提供"使用列表浏览"文字入口。
- 键盘用户可不碰地图完成全部筛选（弹窗 + 列表均可达）。

## 9. 无障碍规范（全站强制）

1. **语义化**：页头 `<header>`、导航 `<nav aria-label>`、主体 `<main>`、页脚 `<footer>`；每个页面有且仅有一个 `<h1>`（站点名或页面主标题）。
2. **图片**：内容图必须有描述性 `alt`；装饰图 `alt=""`；轮播图提供文字标题于 DOM 中（不只烧在图里）。
3. **键盘**：所有交互元素可 Tab 聚焦，`:focus-visible` 显示 2px 朱红描边；弹窗开启时焦点圈定、Esc 可关（Element Plus 默认满足，自定义组件需补）。
4. **对比度**：正文 ≥ 4.5:1，大号标题 ≥ 3:1；占位/禁用文字不得作为唯一信息载体。
5. **表单**：label 与控件显式关联；错误提示 `aria-live` 或由 EP 表单校验输出并被读屏读取。
6. **动效偏好**：全局样式包含 `@media (prefers-reduced-motion: reduce)` 关闭非必要过渡。
7. 每个页面的验收以"纯键盘走通主要路径"为通过标准。

## 10. 接口与请求规范

1. `utils/request.js`（迁移为 `.ts`）为唯一 axios 实例：baseURL 读 `import.meta.env.VITE_API_BASE_URL`，超时 15s，携带 token，401 统一跳登录，业务码非 200 统一 `ElMessage.error` 并 reject。
2. `api/` 模块按域导出类型化函数：`export const getHeritageList = (params: HeritageQuery) => request<PageResult<HeritageItem>>({ url: '/front/heritage/list', method: 'get', params })`。
3. 文件上传走现有 `file.js` 封装，禁止组件内直接 new axios。
4. 新增接口必须先在 docs/08 补文档再写前端调用（毕业设计答辩可追溯）。

## 11. 构建与质量门禁

| 项 | 要求 |
|---|---|
| 构建 | `npm run build`（含 vue-tsc 类型检查）零报错 |
| 控制台 | 浏览器控制台零未捕获错误、零 Vue 警告（演示与验收均以此为准） |
| 依赖 | 不新增重型依赖；确需新增在评审会提出（本规范新增仅：typescript、vue-tsc、@amap/amap-jsapi-loader） |
| 提交 | Conventional Commits（延续现有 `feat()/fix()/docs()` 风格），单次提交聚焦一件事 |
