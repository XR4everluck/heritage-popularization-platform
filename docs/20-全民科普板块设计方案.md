# 20 - "全民科普"板块设计方案（审定稿）

> 定位一句话：面向普通用户（含未登录游客）的 **UGC 浏览入口**，集中展示"用户发布 + 管理员审核通过"的非遗科普快讯与科普视频。
> 与现有板块的关系：首页/非遗博览展示**官方**内容；全民科普展示**用户创作**内容，两个入口定位互补、不互相替代。

---

## 一、核心定位与展示红线

1. **只展示审核通过（status=1）的用户发布内容**。未审核（0）、审核中（0）、未通过（2）的内容在任何视图下都不得出现——该规则由**后端接口保证**（查询条件固定 status=1），而非前端过滤，杜绝绕过。
2. 未登录游客可浏览；发布入口仅登录用户可见（复用现有 JWT 拦截器规则：浏览接口公开、提交接口需登录）。
3. 不展示提交者之外的管理信息（审核意见/审核时间等仅个人中心与管理后台可见）。

## 二、页面与功能设计

### 2.1 入口与路由
- 新路由 `/community`，名称"全民科普"；顶部导航与页脚快捷链接各加入口（位于"非遗地图"之后）。

### 2.2 页面结构（复用现有范式，docs/11）
页头横幅（`gq-page-header`：居中标题 + 对称菱形纹样 + 副题"来自普通用户的非遗科普创作"）
→ **类型筛选**（全部 / 科普快讯 / 科普视频，`el-radio-group`，切换重置分页）
→ **内容列表**（卡片栅格：快讯为图文卡、视频为封面 + 时长角标 + 播放标识别；每卡含标题、关联项目、提交人昵称、发布时间）
→ 统一分页（`AppPagination`）→ 空状态（`el-empty`："还没有用户发布的科普内容"）。

### 2.3 功能清单
| 功能 | 说明 |
|---|---|
| 内容列表 | 仅已通过 UGC，按审核通过时间倒序，后端分页（返回 `{records, total}`，与现有 PageResult 对齐） |
| 类型筛选 | 接口参数 `type=news/course` 传后端，不在前端过滤（保证分页总数正确） |
| 快讯详情 | 弹窗展示（标题 + 正文 + 关联项目链接），复用首页快讯详情交互；**正文用文本插值渲染，不用 v-html**（UGC 为纯文本录入，从源头免疫 XSS） |
| 视频详情 | 弹窗内嵌 B 站官方播放器（复用 CourseDetail 的 BV 解析逻辑），附"在新窗口打开"兜底；不做独立详情页（UGC 为单视频，无需章节体系） |
| 去发布 | 卡片区右上"我要发布"按钮：已登录跳个人中心"内容发布"Tab；未登录跳登录页并携带回跳参数 |

## 三、审核状态与发布状态的关联逻辑

状态机：`0 待审核 →（管理员）→ 1 已通过 / 2 未通过（终态）`。

| 状态 | 个人中心"我的发布" | 管理后台"内容审核" | 全民科普 |
|---|---|---|---|
| 0 待审核 | ✅（含"待审核"标签） | ✅（可操作通过/驳回） | ❌ 永不出现 |
| 1 已通过 | ✅（含"已通过"标签） | ✅（可查审核意见） | ✅ 唯一展示来源 |
| 2 未通过 | ✅（含驳回原因） | ✅ | ❌ 永不出现 |

排序键统一使用**审核时间**（review_time，即"发布时间"）而非提交时间——内容从通过那一刻起才进入公共时间线。

## 四、与现有审核发布流程的衔接

1. **数据同源**：全民科普读取的就是既有 `user_submission` 表（本轮后端已建），不另建数据表；新增一个**公开查询接口**：
   `GET /api/submission/approved?type=&page=&pageSize=` → `{records: SubmissionVO[], total}`；
   需在 `WebMvcConfig` 拦截器白名单加入 `/api/submission/approved`（游客可浏览）。
2. **上游一致**：内容来自个人中心"内容发布"（已实现），审核在后台"内容审核"（已实现），本板块是这条流水线的**展示终点**，不引入新的状态或表。
3. **快讯双出口**：管理员通过快讯时后端会自动写入官方 `heritage_news` 表（已实现），因此同一条快讯可能同时出现在"首页·科普快讯"（官方出口）与"全民科普"（UGC 出口）——这是设计内行为：前者是官方内容流，后者强调用户创作归属，展示字段一致、不冲突。

## 六、边界情况与对策

| # | 边界情况 | 对策 |
|---|---|---|
| 1 | 游客浏览 | 查询接口公开；仅"我要发布"要求登录 |
| 2 | 已通过内容需下架 | 当前状态机无回退（1 为终态）。方案：管理端增加"下架"操作（1→0 并注明原因），全民科普即消失；列为本板块随附小改动，默认实现 |
| 3 | 关联项目被删除 | SubmissionVO 冗余了 heritageName，展示不受外键影响；详情弹窗的"查看关联项目"按钮在该项目不存在时隐藏 |
| 4 | B 站视频被删除/链接失效 | 内嵌播放器呈现 B 站错误页，附"在新窗口打开"兜底链接 |
| 5 | 列表为空 | 空状态 + "去发布"引导 |
| 6 | XSS | UGC 正文纯文本插值渲染，不使用 v-html；标题/昵称同理 |
| 7 | 同一内容两处展示 | 快讯通过后落 heritage_news（首页官方流）+ 全民科普（UGC 流），双出口为设计内行为，无需去重 |
| 8 | 高频灌水 | 暂不做限频；如需要可在后端加"同用户 60 秒内仅可提交一次"（列为可选增强） |
| 9 | 分页边界 | 翻页后切换类型筛选自动回到第 1 页；page 越界后端返回空 records |

## 七、验收要点

- [ ] 待审核/未通过内容在全民科普任何视图不可见（用管理端驳回一条后核验）
- [ ] 类型筛选正确且分页总数随类型变化
- [ ] 游客（未登录）可浏览、点击"我要发布"被引导登录
- [ ] 快讯弹窗正文转义（提交含 `<script>` 字样的内容验证不执行）
- [ ] 视频弹窗可播放 B 站视频，失效链接有兜底
- [ ] 管理端"下架"后内容从全民科普消失
- [ ] 移动端 375px 单列可读、无横向滚动
